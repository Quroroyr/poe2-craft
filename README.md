# PoE 2 Craft Planner

Веб-сервис для крафта в **Path of Exile 2**. Рабочий стол крафта: вставляете исходный предмет и
пример желаемого результата (Ctrl+C из игры), выбираете способ крафта, применяете шаги к текущему
предмету и видите пул модов, шанс цели, потраченное и ожидаемую стоимость с объяснением каждого числа.

> **Демо-данные и демо-симуляция.** Тиры, уровни и веса модов в CraftDB придуманы для проверки
> движка (см. [docs/data-sources.md](docs/data-sources.md)). Кнопка «Применить» разыгрывает
> упрощённую модель, а не реальную механику PoE 2. Реальны только названия баз, валют, Omen,
> тексты статов и иконки: они сверены с официальными данными трейда PoE 2.

## Запуск

Нужны Node.js ≥ 20 и pnpm 10 (`npm i -g pnpm`).

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

Production:

```bash
pnpm build
pnpm start
```

## Проверки

```bash
pnpm test         # unit-тесты всех пакетов + архитектурные (vitest)
pnpm typecheck    # tsc по каждому пакету и сайту
pnpm build        # production-сборка Next.js
pnpm check        # всё сразу
```

## Рабочий стол (v0.3)

```
┌────────────┬──────────────────────┬────────────┐
│ ИСХОДНЫЙ   │ ТЕКУЩИЙ ПРЕДМЕТ      │ ЦЕЛЬ       │
│ импорт +   │ клик = применить     │ импорт +   │
│ ручная     │ активный инструмент  │ требования │
│ правка     │                      │ «тир N+»   │
└────────────┴──────────────────────┴────────────┘
 ИНСТРУМЕНТЫ: Валюта | Omens | Essences… (скоро) + активный инструмент
 ПУЛ МОДОВ (осмотр / правка исходного / правка цели) | ИСТОРИЯ И ЗАТРАТЫ
```

| Сущность | Что это | Чем меняется |
|---|---|---|
| **Исходный** (source) | база, с которой начинаем | импорт Ctrl+C, ручная правка: «+ Добавить префикс/суффикс», «изменить» → тир / заменить / удалить, пустая база |
| **Текущий** (current) | что получилось сейчас | только крафтом: клик по предмету, Ctrl+Z / Ctrl+Shift+Z, откат к шагу, Reset craft |
| **Цель** (target) | требования к результату | импорт примера и/или ручная сборка: «+ Требование», тир «T1 / T2+…», удалить |

**Как крафтить.** Выберите сферу во вкладке «Валюта», при желании Omen во вкладке «Omens», затем
кликайте по текущему предмету. При наведении видно, что произойдёт («Применить: Exalted Orb · 0.01 div»)
или почему нельзя («Нет свободного суффикса»). Клик по невозможному действию ничего не меняет и не стоит.
Доступны только смоделированные инструменты: Exalted Orb, Perfect Exalted Orb (модель с уровнем мода
≥ 50), Exalted Orb + Omen of Dextral/Sinistral Exaltation. Комбинация, которой нет в данных, показана
как «не смоделирована».

**Затраты.** «Потрачено (факт)» — сумма шагов в истории. «Следующий клик» и «Ожидаемо до цели шага» —
оценки. Отменённый шаг вычитается из потраченного; Reset craft обнуляет историю и потраченное.

**Пул модов** — один обозреватель на три режима: осмотр пула текущего предмета для активного
инструмента; выбор мода для исходного (по «+ Добавить…» или «Заменить…»); выбор требования для цели.
Вкладки «Префиксы» / «Суффиксы» (Implicits, Desecrated, Special — заготовки), поиск, фильтр по статусу,
семейства с тегами, раскрываемые тиры с ilvl, уровнем мода, весом, статусом и причиной.

### Ограничения

- Все числа модов — fixture; одна база (Akoyan Spear) и две версии (0.4.0, 0.5.0).
- Результат клика — демо-симуляция (мод по весу, значения равномерно), не механика PoE 2.
- Omen работает только как часть смоделированной комбинации, не как отдельный слой.
- Ожидаемая стоимость — оценка шага в модели «повторять из текущего состояния», не маршрута.
- Маршрут до цели не строится; сессия не сохраняется между перезагрузками.

## Структура

```
apps/web                    сайт Next.js (только отображение и композиция)
packages/craft-domain       типы и чистые правила домена
packages/craft-db           версионная база игровых данных + fixture
packages/item-parser        текст предмета → ItemState
packages/probability-engine пул модов, обозреватель пула, вероятности, объяснение
packages/economy            стоимость попытки и этапа
packages/craft-session      демо-применение действий, сессия, сравнение с целью
docs/                       архитектура, модель, инварианты, источники, ADR 001–005
tests/                      архитектурные проверки и проверка иконок
```
