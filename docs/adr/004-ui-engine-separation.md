# ADR 004 — Разделение UI и движка

Статус: принято (v0.1, 2026-10-02)

## Контекст

Продукт — полноценный веб-сайт, но ядро (парсер, данные, вероятности, экономика) должно
переиспользоваться: на сервере, в API, в будущем солвере, в тестах.

## Решение

- Монорепо pnpm: `apps/web` (Next.js 16, App Router) + пакеты в `packages/*`.
- Пакеты поставляются как исходники TypeScript (`exports: ./src/index.ts`) и компилируются
  Next через `transpilePackages`. Шага сборки пакетов нет.
- Пакеты не зависят от React/Next.js; это проверяет `tests/architecture.test.ts`.
- В веб-приложении:
  - `src/lib/analyze.ts` — композиция: парсер → пул → вероятность → объяснение. Игровых правил нет.
  - `src/lib/texts.ts` — формулировки для кодов причин и статусов (русский).
  - `src/lib/format.ts`, `prices.ts`, `icons.ts` — форматирование, разбор полей ввода,
    сопоставление игровых art id с локальными иконками.
  - `src/components/*` — отображение. Расчёты только вызовами функций пакетов в `useMemo`.
- Страница статическая (`○ /`), всё считается в браузере. Сервер в v0.1 не нужен.

## Последствия

- Перенос расчёта на сервер (API route или Server Action) — замена одного вызова `analyzeStage`.
- Тексты отделены от кодов, поэтому локализация добавляется без изменений в движке.
- Цена: пакеты должны оставаться совместимыми с бандлером Next (ESM, без node-only API).
