# ADR 002 — Версионная CraftDB

Статус: принято (v0.1, 2026-10-02)

## Контекст

Правила PoE 2 меняются от лиги к лиге (0.5.x, 0.6.x, …). Нужно, чтобы расчёт всегда шёл по
правилам одной версии, а старые предметы и расчёты оставались воспроизводимыми.

## Решение

- У каждой записи данных есть `versions: { introducedIn, removedIn?, changedIn? }`, где
  `removedIn` не включается.
- **Изменение значения = новая ревизия с тем же stable id** и непересекающимся диапазоном версий.
  `validateDataset` запрещает пересечения. Пример в fixture — `mod.local-attack-speed.t1`
  (вес 600 в 0.4.0 и 400 с 0.5.0).
- Доступ к данным только через `CraftDb.forVersion(v) → CraftDbView`. View отдаёт ровно одну
  живую ревизию каждого id. Версии вне `DatasetInfo.gameVersions` — ошибка
  `UnsupportedGameVersionError`, а не тихий пустой результат.
- Группы и цели не версионируются: они влияют на расчёт только через живые моды.
- Набор данных — сериализуемый `CraftDataset`, сейчас TypeScript-модуль. Позже его можно грузить
  из JSON или по сети без изменения API.
- `DatasetInfo.kind: 'fixture' | 'production'` — только для отображения; логика на нём не ветвится.

## Последствия

- Миграций и автообновления нет. Добавить патч = добавить ревизии и версию в `gameVersions`.
- Предмет, сохранённый в одной версии, пересчитывается в другой; моды, которых в ней нет,
  дают caveat `modifier-missing-in-version`.
- View кэшируется на версию. Для больших наборов индексация может понадобиться раньше, чем
  сейчас (`listModifiers` — линейный проход), но это вопрос производительности, а не API.
