# ADR 008 — Интерфейс по утверждённому макету: полоса инструментов, Omen как модификатор, статусы цели

Статус: принято (v0.5, 2026-10-02)

## Контекст

Владелец утвердил макет интерфейса: три предмета в верхнем ряду, широкая полоса инструментов крафта,
внизу пул модов, история и затраты. В макете полоса показывает много игровых валют (Divine, Chaos,
Annulment, …), у целевых модов есть статусы «есть / не хватает / докрафтить», а Omen ощущается как
модификатор выбранной валюты. Правило ADR 006 «палитра показывает только расходники смоделированных
действий» с этим несовместимо.

## Решение

1. **Палитра показывает все известные расходники версии** (`toolPalette` → `byCategory` + `modelled`).
   Расходник, которого не тратит ни одно действие, помечен «не смоделировано»: его можно взять в руку,
   увидеть совместимость, но клик по предмету отклоняется и ничего не стоит. Механику это не изобретает:
   действие по-прежнему находится только в данных (инвариант 30 остаётся). Заменяет пункт 1 ADR 006 в
   части «что показывает палитра».
2. **Категории расходников** расширены: `currency | omen | essence | catalyst | rune` (по группам
   официального трейда). Новые записи — `fixtures/consumables.ts`: реальные названия и арт из
   `trade2/data/static`.
3. **Omen — модификатор валюты, а не отдельный флажок.** `ToolSelection` держит Omen независимо от
   смены валюты; убрать его можно только явно. `Consumable.modifies` (данные, experimental) говорит, к
   какой валюте Omen относится. `resolveTool` различает: `ready` (есть действие), `incompatible` (Omen не
   для этой валюты), `unsupported` (совместимо, но не смоделировано), `none` (валюты нет; Omen ждёт).
   `applyToolStep` отклоняет `incompatible` / `unsupported` без трат.
4. **Статус каждого требования цели** — `targetOutlook` в craft-session: `done` (есть), `craft`
   (докрафтить: семейство можно добавить сейчас — по manual-edit пулу текущего предмета), `missing` (не
   хватает: места нет / группа занята / ilvl мал / нужен fractured), `worse-tier`, `not-fractured`,
   `unknown`; плюс прогресс `done / total`. «Можно добавить» — правило законности, а не шанс конкретной
   валюты.
5. **Факт и оценка разведены и в таблице затрат:** `sessionSpentByConsumable` раскладывает потраченное
   по расходникам из записанных шагов; ожидаемые числа этапа показаны отдельно.
6. **Время шагов хранит страница** (`WeakMap<CraftStepRecord, number>`), а не сессия: ядро остаётся без
   часов (инвариант 12).
7. **Фон** — сгенерированная локально картинка (Z-Image-Turbo, Apache 2.0) тёмной мастерской со свечами,
   сильно приглушённая. Это оформление, а не игровой ассет; игровые картинки — только из официальных
   данных (`art-manifest.ts`).

## Последствия

- Новая механика по-прежнему начинается с действия в данных; её расходник уже виден в палитре и сам
  перестанет быть «не смоделировано», когда действие появится.
- Неверная область Omen в данных даст неверное «несовместимо», но не неверный расчёт: области помечены
  experimental и не участвуют в вероятностях.
