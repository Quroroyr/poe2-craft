# ADR 009 — Ручная правка текущего предмета как шаг сессии; контекстное меню модов

Статус: принято (v0.6, 2026-10-02)

## Контекст

После симуляции крафта пользователю нужно пробовать «а что, если»: поднять тир выпавшего мода,
отметить его fractured, убрать мод, заменить его другим. До сих пор текущий предмет менялся только
craft-шагом, undo / redo и reset (инварианты 22, 29). Если разрешить сайту собирать `ItemState`
текущего предмета напрямую, такие правки:

- выпадут из undo / redo и истории;
- смешаются с крафтом (как будто это Annulment / Fracturing Orb / Chaos Orb);
- либо попадут в «потрачено», либо незаметно сделают его неполным.

## Решение

1. **История сессии — два вида шагов.** `SessionStep = CraftStepRecord | ManualEditStepRecord`
   (`kind: 'craft' | 'manual-edit'`). Оба двигают `current` от `before` к `after`, поэтому
   `undoLastStep` / `redoStep` / `undoToStep` / `resetToSource` работают с ними одинаково; redo
   возвращает записанный `after`, без нового броска. Любой новый шаг (крафт или правка) стирает
   redo-ветку.
2. **`ManualEditStepRecord`**: `index` (позиция в общей истории), `operation`
   (`add | retier | remove | replace | fracture | unfracture`), `modifierIndex` (позиция мода в `before`;
   у `add` — его позиция в `after`),
   `label` (текст для логов и экспорта), `from` / `to` (мод до и после: id, текст, тир, сторона; `to`
   — null при удалении, `from` — null при добавлении), `before`, `after`. Стоимости нет — поля `cost` у этого шага нет вообще.
3. **`applyManualEdit(session, db, edit)`** (craft-session) — единственный вход для правки current.
   Правила предмета те же, что у настройки исходного: новый тир / мод проверяется по manual-edit пулу
   предмета без старого мода (`sourcePickOptions`); тир меняется только внутри семейства и только на
   существующий тир (`currentTierOptions` / `betterTierOption`, без `tier - 1`). Отказ возвращает ту же
   сессию с кодом и причинами.
4. **Потрачено считает только craft-шаги** (`craftSteps`, `sessionSpent`, `sessionSpentByConsumable`).
   Если в активной ветке есть правка (`hasManualEdits`), панель затрат говорит, что «потрачено»
   объясняет не весь предмет. Оценки (стоимость клика, ожидаемая стоимость этапа) от этого не
   меняются.
5. **Ручная правка ≠ игровая механика.** Удаление — не Annulment, fractured — не Fracturing Orb, смена
   тира — не целевое улучшение. Эти механики появятся отдельными вероятностными `CraftAction`.
   Визуально правка отличается: карандаш и штриховка в истории, пунктирный бейдж «вручную» на моде,
   одноразовое предупреждение перед первой правкой в сессии страницы.
6. **Замена из пула — тот же пикер.** Новый режим обозревателя `edit-current` (`PoolMode` и
   `ExplorerMode`, `replaceIndex`) оценивает текущий предмет без заменяемого мода; клик по строке тира
   — `applyManualEdit({ operation: 'replace' })`. Поведение пикера v0.5.1 сохраняется.
9. **Добавление в свободный слот (патч после v0.8).** `edit-current` без `replaceIndex`, но со `side`
   — «добавить мод»: кнопки «+ Добавить префикс / суффикс» на текущем предмете открывают пул на этой
   стороне. Правила те же, что у пула (`manualAddAction(side)` = manual-edit пул, ограниченный стороной;
   `currentAddOptions`): база, ilvl, занятые группы, лимиты слотов, домен. Семейство, уже стоящее на
   предмете, при добавлении блокируется группой, а не подменяется — замена остаётся отдельным путём
   (ПКМ → «Заменить из пула»). Видимость кнопок решает `manualAddSlots` по реальным `AffixLimits`
   редкости и класса — React не считает слоты. Клик по тиру — `applyManualEdit({ operation: 'add' })`:
   шаг истории, без цены и броска, undo / redo как у остальных правок, одноразовое предупреждение то же.
10. **«+ Добавить» прямо в обычном пуле.** В режиме inspect у каждой строки тира — кнопка «+» (и пункт
    «Добавить в текущий предмет» в ПКМ по строке): второй вход в тот же `applyManualEdit({ operation: 'add' })`.
    У строки два независимых состояния: статус строки, вес и доля — пул держимого инструмента
    (Exalted + Omen), а доступность «+» — `currentAddOptions` без стороны (правила ручной правки
    текущего предмета; держимая валюта и Omen их не сужают). Недоступный «+» неактивен и называет
    причину (`ExclusionReason`); семейство, уже стоящее на предмете, не подменяется. После добавления
    пул остаётся в inspect на той же вкладке и семействе.
7. **Контекстное меню — данные, а не правила.** `apps/web/src/lib/mod-menu.ts` строит пункты для
   current / source / target из функций craft-session и описывает их намерениями (`MenuIntent`);
   `Workspace` выполняет намерения. Меню открывается правым кликом и кнопкой «…» у каждой строки.
   Для source намерения — функции настройки (`replaceSourceModifier`, `setSourceModifierFractured`,
   …): не шаг и не трата. Для target — функции `TargetSpec` (`setRequirementTier`,
   `setRequirementFractured`, `removeRequirement`); `addModifierToTarget` не создаёт второе требование
   того же семейства, а переносит минимальный тир.
8. **Отметки модов на текущем предмете** (`currentModifierMarks`) вычисляются проходом по шагам
   активной ветки по позициям: craft добавляет в конец, удаление убирает позицию, остальные правки
   помечают её. Идентичность объектов для этого не годится — `createItemState` копирует моды.

## Последствия

- Инвариант 22 («current меняется только через applyStep / undo / startFromSource») и 29 заменены:
  current меняется только операциями сессии — CraftStep, ManualEditStep, undo / redo, reset.
  React-компоненты `ItemState` не собирают.
- Код, читавший `session.steps` как craft-шаги, обязан различать `kind` (`craftSteps`, `isCraftStep`).
- Правка current не трогает source и target; правка source не пишет шагов и не стоит денег (ADR 007).
