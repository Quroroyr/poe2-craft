# ADR 006 — Рабочий стол: инструмент → клик по предмету, редактируемые Source и Target

Статус: принято (v0.3, 2026-10-02)

## Контекст

В v0.2 крафт выглядел как форма: выбрать действие в списке и нажать «Применить». Исходный
предмет можно было только вставить текстом, а цель была конкретным предметом с выпавшими
числами. Для будущего солвера цель должна быть набором требований, а не примером ролла.

## Решение

1. **Инструмент, затем клик по предмету.** Палитра хранит `ToolSelection`
   `{ currencyId, omenIds }`. `resolveTool` ищет действие, у которого `defaultCost` состоит ровно из
   выбранных расходников. Комбинация, которой нет в данных, получает статус `unsupported` и не
   применяется. Новых правил «валюта + omen» код не придумывает. Палитра показывает только
   расходники, которые тратит хотя бы одно реализованное действие (`toolPalette`).
2. **Предпросмотр совпадает с кликом.** `checkApplicable(pool)` используется и для подсказки при
   наведении («Нельзя: нет свободного суффикса»), и внутри `applyAction`. Добавлена причина
   `no-free-slot`.
3. **Source редактируется вручную** (`addSourceModifier`, `removeSourceModifier`,
   `replaceSourceModifier`, `blankItem`). Ручная правка не крафт и ничего не стоит. Значения
   ставятся в середину диапазона: пользователь выбирает тир, а не ролл. `setSource` до первого шага
   тянет за собой current, после — нет: `isSourceOutOfSync` показывает баннер с Reset.
4. **Target — это `TargetSpec` из `TargetRequirement`** (craft-domain). Требование = стабильный id
   минимально приемлемого тира + флаг fractured + происхождение (import / manual). «Тир N или лучше» =
   тот же набор групп и та же сторона, tier ≤ N. Импорт примера превращает распознанные моды в
   требования, а нераспознанные строки сохраняет как текст. Точные значения, точный тир,
   необязательные моды и OR-группы — будущие расширения требования.
5. **Один обозреватель пула, три режима** (`poolForMode`): `inspect` (текущий предмет + активный
   инструмент), `edit-source` (исходный по правилам ручной правки, с `replaceIndex` для замены),
   `edit-target` (требования как предмет: `targetAsItem`). Для режимов правки используется
   `MANUAL_EDIT_ACTION` — набор правил «что может законно стоять на предмете», он никогда не
   передаётся в `applyAction`. Чтобы так можно было, `buildEligiblePool` принимает действие и объектом,
   а не только по id.
6. **Undo / Redo / откат к шагу / Reset.** `CraftSession.redoStack`. Undo переносит шаг в redo,
   Redo возвращает его без нового броска, новый клик очищает redo. `undoToStep` откатывает к
   выбранному шагу истории. `resetToSource`: current = source, история и redo пусты, потрачено = 0.
   Source и target не меняются. Горячие клавиши: Ctrl+Z, Ctrl+Shift+Z / Ctrl+Y (вне полей ввода).
7. **Категория расходника** (`Consumable.category`: currency / omen / essence) — данные, по
   группам официального трейда; от неё зависит только палитра.

## Последствия

- Солвер получит цель в виде требований и сможет планировать к «тир N или лучше».
- Новая механика сначала появляется как действие в данных; тогда же её расходники автоматически
  попадают в палитру. Вкладки без моделей видны, но пусты («скоро»).
- Omen пока работает как часть действия (комбинация в данных), а не как отдельный слой эффектов.
  Отдельный слой потребует композиции эффектов (`CraftEffect`) — следующий шаг.
