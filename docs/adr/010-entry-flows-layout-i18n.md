# ADR 010 — Входные сценарии, раскладка «текущий + цель» и язык интерфейса EN / RU

Статус: принято (v0.7, 2026-10-02)

## Контекст

Экран повторял архитектуру: три равные колонки «Исходный | Текущий | Цель». После начала крафта
исходный — это только снимок старта, а работа идёт на текущем предмете; цель — постоянный ориентир.
Кроме того, сайт при первом открытии сам подставлял демо-предмет и демо-цель, а весь интерфейс был
зашит по-русски, хотя игровые термины и основная аудитория PoE — англоязычные.

## Решение

1. **Архитектура ≠ раскладка.** `CraftSession { source, current, target }` не меняется: исходный остаётся
   отдельной сущностью сессии, ручные правки current — по ADR 009 без изменений. Меняется только экран:
   - верх: **текущий предмет — большой верстак** (~2/3 ширины) и **цель справа** (~1/3), на ≤ 900 px — одна
     колонка;
   - исходный свёрнут в строку над текущим («Исходный: база · редкость · ilvl · моды · fractured») с
     действиями «Изменить исходный», «Сбросить к исходному», «Импортировать другой»;
   - низ: инструменты, пул модов, история, затраты, «Как посчитано».
2. **Новая сессия пуста.** `source = current = target = null`, истории и затрат нет. Демо-образцы
   остаются только для тестов и как кнопки «Демо-примеры» в окне импорта; сами они не загружаются.
3. **Входные сценарии — UI-состояние, не домен.** `Workspace` держит экран (`start` — нет текущего;
   `setup` — поверхность настройки исходного; активная работа) и диалоги (импорт, превью,
   подтверждение). В `craft-domain` / `craft-session` ничего из этого нет.
4. **Импорт — один путь.** Ctrl+V в любом месте страницы (не в поле ввода, не поверх открытого
   окна) и кнопка «Импорт предмета» ведут в `recognizeItem` (предмет = распознаны редкость или класс) →
   одно превью (база, редкость, ilvl, число префиксов / суффиксов / fractured, нераспознанные строки) →
   «Начать крафт». До подтверждения сессия не меняется. Подтверждение = `startFromSource`.
5. **Ctrl+V при активном крафте не заменяет сессию молча.** То же превью с вопросом «Начать новый крафт
   с этим предметом?». При подтверждении: новый исходный, current = source, история и затраты сброшены.
   **Цель сохраняется всегда**: пустая цель следует за новой базой, цель с требованиями на другой базе
   остаётся и показывается с существующим предупреждением о несовпадении баз (шансы к ней не считаются).
6. **«Создать предмет» и «Изменить исходный» — одна поверхность настройки** (`SourceSetupSurface`):
   существующие `SourcePanel`, `BaseSelector`, пул-пикер (режим `edit-source`) и контекстное меню
   исходного работают над черновиком; в сессию он попадает только по «Создать предмет» / «Сохранить
   исходный». Сохранение после начала крафта — `setSource` (семантика v0.6: current не трогается,
   показывается рассинхрон и «Сбросить к исходному»).
7. **Цель постоянно справа.** Пустая цель объясняет, что она даёт, и предлагает «Собрать цель» (база
   текущего, затем пикер требований), «Импорт цели» (тот же диалог импорта) и «Взять текущий как
   основу» — `targetSpecFromItem(current)`: та же база и ilvl, каждый мод становится требованием
   «этот тир или лучше» (fractured сохраняется); выпавшие числа не копируются. Статусы требований —
   по-прежнему `targetOutlook` ядра.
8. **Язык интерфейса — EN / RU.** `apps/web/src/i18n`: типизированные ключи (`en.ts` — эталон и запасной
   язык, `ru.ts` обязан иметь те же ключи — проверяет тип `Messages` и тест), `t(key, params)` с
   подстановкой `{name}` и множественным числом через `Intl.PluralRules`, форматирование чисел и времени
   по языку. `I18nProvider`: новый посетитель — EN, выбор хранится в `localStorage`
   (`poe2-craft.locale`) и восстанавливается; переключатель — в шапке. Язык — состояние
   представления: пакеты, данные и правила его не видят. Игровые названия (базы, валюты, тексты модов,
   теги) не переводятся.
9. **Шапка показывает только то, что есть:** раздел «Крафт», версия игры, EN / RU, «Демо-данные».
   «Моды», «База предметов», «Симуляции» убраны до появления страниц.

## Последствия

- Компоненты не держат текст: всё через `t()`; тест `i18n/core.test.ts` падает, если в коде компонентов
  или `lib/` появится кириллица вне комментариев.
- `lib/texts.ts`, `lib/mod-menu.ts`, `lib/session-ui.ts`, `lib/held-tool.ts` принимают переводчик.
- Тесты сайта рендерят `Workspace` через `test-utils.tsx` (язык и демо-сессия задаются явно).
- Уведомление о шаге написано на языке момента; при смене языка оно сбрасывается.
