# Инварианты крафта

Правила, которые нельзя случайно сломать. Нарушение одного из них — повод остановиться и
обсудить, а не «быстро поправить». Часть правил проверяют тесты (указано в скобках).

1. **UI не рассчитывает вероятности крафта.** Компоненты вызывают `probability-engine` и
   `economy` и форматируют результат. Даже доля мода в пуле берётся из `ProbabilityOk.outcomes`.
2. **UI не содержит игровых правил.** Слоты, коллизии, ilvl, веса, стороны — только в пакетах.
   `apps/web/src/lib/texts.ts` лишь подбирает слова к кодам.
3. **CraftDB не зависит от React.** (`tests/architecture.test.ts`)
4. **Probability Engine не зависит от React/Next.js.** (`tests/architecture.test.ts`)
5. **ItemState ссылается на моды через stable id.** Определение в состояние не копируется.
6. **ModifierDefinition хранится в CraftDB** и берётся через `CraftDbView` нужной версии.
7. **GameVersion — часть CraftContext.** Любой расчёт начинается с `db.forVersion(context.gameVersion)`.
8. **Неизвестный вес нельзя молча считать достоверным.** `weight: null` даёт либо
   `bound: 'upper-bound'` (неизвестен вес конкурента), либо `indeterminate` (неизвестен вес цели).
   Подставлять 0 или среднее запрещено. (`probability.test.ts › unknown weights`)
9. **Fixture-данные явно отличаются от production.** `DatasetInfo.kind === 'fixture'`, источник
   `kind: 'fixture'`, баннер на сайте, caveat `fixture-dataset` в объяснении. Бизнес-логика
   на `kind` не ветвится.
10. **Каждое игровое правило имеет source/confidence.** Все записи датасета несут `Provenance`;
    `validateDataset` отклоняет ссылки на несуществующий источник.
11. **Правило PoE 1 не становится правилом PoE 2 без отдельного подтверждения.** Такой
    перенос допустим только с `confidence: 'experimental'` и пометкой в `notes`.
12. **Расчёт детерминирован.** Одинаковый вход → одинаковый выход: без `Math.random`, времени
    и глобального состояния. Распределения считаются аналитически. (`is deterministic for the same input`)
    Демо-симуляция в `craft-session` тоже детерминирована при заданном seed (см. 24).
13. **Domain API не меняется ради удобства одной React-компоненты.** Не хватает данных —
    добавьте функцию-адаптер в `apps/web/src/lib`.

Дополнительные инварианты:

14. **Ни одна строка предмета не теряется.** Нераспознанное попадает в `UnresolvedModifier` или
    `otherLines` и показывается пользователю. Парсер не бросает исключений на любом тексте.
15. **При неопределённости — осторожная оценка и предупреждение.** Нераспознанная строка
    занимает слот; известная по шаблону группа считается занятой; результат несёт `caveats`.
16. **Ни одно исключение мода не бывает без причины.** `PoolEntry.eligible === (reasons.length === 0)`;
    у исключённого мода есть все применимые причины, а не только первая.
17. **Данные не подгоняются под нужный процент.** Числа в тестах выводятся из fixture вручную
    (вывод записан комментарием в `probability.test.ts`); меняется fixture — меняются тесты.
18. **Ревизии одного id не пересекаются по версиям.** (`validateDataset`)
19. **Ожидаемая стоимость всегда показывается вместе с разбросом** (квантили 50/75/90/95%):
    одно среднее вводит в заблуждение при RNG.
20. **Нельзя смешивать единицы цен.** Один `PriceSnapshot` — одна единица; конвертация валют
    потребует курсов со своим provenance.

Инварианты рабочего стола (v0.2):

21. **Источник, текущий и целевой предметы — разные сущности.** Действия меняют только `current`;
    `source` и `target` меняются только вставкой нового текста. (`keeps source, current and target apart`)
22. **Текущий предмет меняется только через `applyStep` / `undoLastStep` / `startFromSource`.**
    Сайт не собирает `ItemState` руками и не мутирует его.
23. **Отказ ничего не меняет.** Невозможное действие возвращает ту же сессию: предмет тот же,
    шаг не записан, затраты не выросли. (`a rejected action changes nothing and spends nothing`)
24. **Случайность только через переданный `Rng`.** В пакетах нет `Math.random`; seed генерирует
    сайт. Одинаковые `(seed, rollCount)` → одинаковый бросок. (`is reproducible from its seed`)
25. **Демо-симуляция всегда подписана как демо.** Пока механики не подтверждены данными,
    результат «Применить» не выдаётся за поведение игры.
26. **Факт и оценка не смешиваются.** «Потрачено» = сумма записанных шагов по ценам на момент шага;
    стоимость попытки и ожидаемая стоимость этапа — оценки и показываются отдельно.
27. **Неизвестный вес блокирует симуляцию.** Если вес хотя бы одного мода пула неизвестен,
    `applyAction` отказывает (`unknown-weights`), а не выбирает по известной части.
28. **Действие не подменяет чужую механику.** `applyAction` разбирает `effect.kind` явно;
    у нового вида эффекта должна быть своя реализация, иначе он не применяется.

Инварианты v0.3:

29. **Крафт меняет только current.** Ручная правка меняет только source или target и ничего не
    стоит. (`changes only the current item…`, `adds and removes source modifiers…`)
30. **Инструмент не изобретает механику.** Комбинация «сфера + omen» применима, только если в
    данных есть действие ровно с такими расходниками; иначе `unsupported`.
    (`does not invent an action for a combination nobody modelled`)
31. **Подсказка до клика = результат клика.** Предпросмотр и `applyAction` используют один
    `checkApplicable`.
32. **Цель — требования, а не ролл.** `TargetRequirement` хранит минимально приемлемый тир;
    конкретные выпавшие числа примера в цель не попадают.
33. **Undo честен к деньгам.** Потрачено = сумма неотменённых шагов; redo возвращает тот же шаг без
    нового броска; новый клик сбрасывает redo; reset обнуляет историю и потраченное, не трогая source и target.
34. **Правила ручной правки (`MANUAL_EDIT_ACTION`) не передаются в `applyAction`.**

Инварианты v0.4 (конструктор базы и настройка исходного, ADR 007):

35. **Настройка исходного — не крафт.** Выбор базы, ilvl, качество, слоты, добавление/удаление/смена
    тира стартовых модов и отметка fractured меняют только source: шагов нет, потраченное не меняется,
    после начала крафта current догоняет source только через Reset. (`a fracture edit of the source costs nothing…`)
36. **Fractured при настройке ≠ Fracturing Orb.** Флаг описывает уже существующий fractured-мод
    стартового предмета. Механика Fracturing Orb будет отдельным `CraftAction` со своей ценой.
37. **Качество и слоты не влияют на расчёт без отдельного правила.** Они хранятся в `ItemState` и
    показываются; пул и вероятности от них не зависят. (`quality and slots change nothing in the pool…`)
38. **Определение базы ≠ состояние предмета.** `ItemState` хранит `baseId`; арт, свойства, теги и
    правила настройки живут только в `ItemBase` в CraftDB. (`creates a blank rare source from a base…`)
39. **Арт — не зависимость домена.** Домен хранит `artAssetId`; путь к файлу, размер и источник знает
    только манифест сайта. Картинки лежат локально, у каждой записан источник. (`tests/icons.test.ts`)
40. **Предлагается только то, что база поддерживает.** Свойство настройки без правила у базы не
    показывается; значения вне правила не принимаются. (`changes quality within the base rule…`)
41. **Цель на другой базе не планируется.** При несовпадении баз — предупреждение, без целей шага.
42. **Fractured-требование выполняется только fractured-модом** и не планируется действиями
    «добавить мод». (`a fractured requirement is not met by a plain modifier…`)
43. **Курсор с валютой ничего не применяет.** Применяет только клик по предмету (`applyToolStep`);
    оверлей не перехватывает события и скрыт от вспомогательных технологий. (`held-tool.test.tsx`)

Инварианты v0.5 (интерфейс по макету, ADR 008):

44. **Показан — не значит смоделирован.** Палитра показывает все расходники, но клик применяет только
    действие из данных; «не смоделировано» и «несовместимо» отклоняются без трат.
    (`a click with an incompatible or unmodelled tool changes nothing and spends nothing`)
45. **Omen не теряется молча.** Смена валюты сохраняет выбранный Omen; совместимость всегда показана.
    (`switching the currency keeps the omen held`)
46. **Статус цели считает ядро.** «Есть / докрафтить / не хватает / тир хуже / не fractured» и прогресс —
    `targetOutlook`, а не JSX. (`gives every requirement its own state against the current item`)
47. **Одна база — одна картинка.** Арт берётся из определения базы по `baseId`; исходный, текущий и цель
    одной базы показывают один и тот же файл. (`art.test.tsx`)
