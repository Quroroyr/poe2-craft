# Инварианты крафта

Правила, которые нельзя случайно сломать. Нарушение одного из них — повод остановиться и
обсудить, а не «быстро поправить». Часть правил проверяют тесты (указано в скобках).

1. **UI не рассчитывает вероятности крафта.** Компоненты вызывают `probability-engine` и
   `economy` и форматируют результат. Даже доля мода в пуле берётся из `ProbabilityOk.outcomes`.
2. **UI не содержит игровых правил.** Слоты, коллизии, ilvl, веса, стороны — только в пакетах.
   `apps/web/src/lib/texts.ts` лишь подбирает слова к кодам.
3. **CraftDB не зависит от React.** (`tests/architecture.test.ts`)
4. **Probability Engine не зависит от React/Next.js.** (`tests/architecture.test.ts`)
5. **ItemState ссылается на моды через stable id.** Определение в состояние не копируется.
6. **ModifierDefinition хранится в CraftDB** и берётся через `CraftDbView` нужной версии.
7. **GameVersion — часть CraftContext.** Любой расчёт начинается с `db.forVersion(context.gameVersion)`.
8. **Неизвестный вес нельзя молча считать достоверным.** `weight: null` даёт либо
   `bound: 'upper-bound'` (неизвестен вес конкурента), либо `indeterminate` (неизвестен вес цели).
   Подставлять 0 или среднее запрещено. (`probability.test.ts › unknown weights`)
9. **Fixture-данные явно отличаются от production.** `DatasetInfo.kind === 'fixture'`, источник
   `kind: 'fixture'`, баннер на сайте, caveat `fixture-dataset` в объяснении. Бизнес-логика
   на `kind` не ветвится.
10. **Каждое игровое правило имеет source/confidence.** Все записи датасета несут `Provenance`;
    `validateDataset` отклоняет ссылки на несуществующий источник.
11. **Правило PoE 1 не становится правилом PoE 2 без отдельного подтверждения.** Такой
    перенос допустим только с `confidence: 'experimental'` и пометкой в `notes`.
12. **Расчёт детерминирован.** Одинаковый вход → одинаковый выход: без `Math.random`, времени
    и глобального состояния. Распределения считаются аналитически. (`is deterministic for the same input`)
    Демо-симуляция в `craft-session` тоже детерминирована при заданном seed (см. 24).
13. **Domain API не меняется ради удобства одной React-компоненты.** Не хватает данных —
    добавьте функцию-адаптер в `apps/web/src/lib`.

Дополнительные инварианты:

14. **Ни одна строка предмета не теряется.** Нераспознанное попадает в `UnresolvedModifier` или
    `otherLines` и показывается пользователю. Парсер не бросает исключений на любом тексте.
15. **При неопределённости — осторожная оценка и предупреждение.** Нераспознанная строка
    занимает слот; известная по шаблону группа считается занятой; результат несёт `caveats`.
16. **Ни одно исключение мода не бывает без причины.** `PoolEntry.eligible === (reasons.length === 0)`;
    у исключённого мода есть все применимые причины, а не только первая.
17. **Данные не подгоняются под нужный процент.** Числа в тестах выводятся из fixture вручную
    (вывод записан комментарием в `probability.test.ts`); меняется fixture — меняются тесты.
18. **Ревизии одного id не пересекаются по версиям.** (`validateDataset`)
19. **Ожидаемая стоимость всегда показывается вместе с разбросом** (квантили 50/75/90/95%):
    одно среднее вводит в заблуждение при RNG.
20. **Нельзя смешивать единицы цен.** Один `PriceSnapshot` — одна единица; конвертация валют
    потребует курсов со своим provenance.

Инварианты рабочего стола (v0.2):

21. **Источник, текущий и целевой предметы — разные сущности.** Действия меняют только `current`;
    `source` и `target` меняются только вставкой нового текста. (`keeps source, current and target apart`)
22. **Текущий предмет меняется только операциями сессии** (с v0.6, ADR 009): craft-шаг
    (`applyStep` / `applyToolStep`), шаг ручной правки (`applyManualEdit`), undo / redo
    (`undoLastStep` / `redoStep` / `undoToStep`) и reset (`resetToSource` / `startFromSource`).
    Сайт не собирает `ItemState` руками и не мутирует его.
23. **Отказ ничего не меняет.** Невозможное действие возвращает ту же сессию: предмет тот же,
    шаг не записан, затраты не выросли. (`a rejected action changes nothing and spends nothing`)
24. **Случайность только через переданный `Rng`.** В пакетах нет `Math.random`; seed генерирует
    сайт. Одинаковые `(seed, rollCount)` → одинаковый бросок. (`is reproducible from its seed`)
25. **Демо-симуляция всегда подписана как демо.** Пока механики не подтверждены данными,
    результат «Применить» не выдаётся за поведение игры.
26. **Факт и оценка не смешиваются.** «Потрачено» = сумма записанных шагов по ценам на момент шага;
    стоимость попытки и ожидаемая стоимость этапа — оценки и показываются отдельно.
27. **Неизвестный вес блокирует симуляцию.** Если вес хотя бы одного мода пула неизвестен,
    `applyAction` отказывает (`unknown-weights`), а не выбирает по известной части.
28. **Действие не подменяет чужую механику.** `applyAction` разбирает `effect.kind` явно;
    у нового вида эффекта должна быть своя реализация, иначе он не применяется.

Инварианты v0.3:

29. **Крафт меняет только current.** Настройка исходного меняет только source, правка цели — только
    target; ни то ни другое ничего не стоит. Ручная правка current — отдельный шаг истории (инварианты
    51–55). (`changes only the current item…`, `adds and removes source modifiers…`)
30. **Инструмент не изобретает механику.** Комбинация «сфера + omen» применима, только если в
    данных есть действие ровно с такими расходниками; иначе `unsupported`.
    (`does not invent an action for a combination nobody modelled`)
31. **Подсказка до клика = результат клика.** Предпросмотр и `applyAction` используют один
    `checkApplicable`.
32. **Цель — требования, а не ролл.** `TargetRequirement` хранит минимально приемлемый тир;
    конкретные выпавшие числа примера в цель не попадают.
33. **Undo честен к деньгам.** Потрачено = сумма неотменённых шагов; redo возвращает тот же шаг без
    нового броска; новый клик сбрасывает redo; reset обнуляет историю и потраченное, не трогая source и target.
34. **Правила ручной правки (`MANUAL_EDIT_ACTION`) не передаются в `applyAction`.**

Инварианты v0.4 (конструктор базы и настройка исходного, ADR 007):

35. **Настройка исходного — не крафт.** Выбор базы, ilvl, качество, слоты, добавление/удаление/смена
    тира стартовых модов и отметка fractured меняют только source: шагов нет, потраченное не меняется,
    после начала крафта current догоняет source только через Reset. (`a fracture edit of the source costs nothing…`)
36. **Fractured при настройке ≠ Fracturing Orb.** Флаг описывает уже существующий fractured-мод
    стартового предмета. Механика Fracturing Orb будет отдельным `CraftAction` со своей ценой.
37. **Качество и слоты не влияют на расчёт без отдельного правила.** Они хранятся в `ItemState` и
    показываются; пул и вероятности от них не зависят. (`quality and slots change nothing in the pool…`)
38. **Определение базы ≠ состояние предмета.** `ItemState` хранит `baseId`; арт, свойства, теги и
    правила настройки живут только в `ItemBase` в CraftDB. (`creates a blank rare source from a base…`)
39. **Арт — не зависимость домена.** Домен хранит `artAssetId`; путь к файлу, размер и источник знает
    только манифест сайта. Картинки лежат локально, у каждой записан источник. (`tests/icons.test.ts`)
40. **Предлагается только то, что база поддерживает.** Свойство настройки без правила у базы не
    показывается; значения вне правила не принимаются. (`changes quality within the base rule…`)
41. **Цель на другой базе не планируется.** При несовпадении баз — предупреждение, без целей шага.
42. **Fractured-требование выполняется только fractured-модом** и не планируется действиями
    «добавить мод». (`a fractured requirement is not met by a plain modifier…`)
43. **Курсор с валютой ничего не применяет.** Применяет только клик по предмету (`applyToolStep`);
    оверлей не перехватывает события и скрыт от вспомогательных технологий. (`held-tool.test.tsx`)

Инварианты v0.5 (интерфейс по макету, ADR 008):

44. **Показан — не значит смоделирован.** Палитра показывает все расходники, но клик применяет только
    действие из данных; «не смоделировано» и «несовместимо» отклоняются без трат.
    (`a click with an incompatible or unmodelled tool changes nothing and spends nothing`)
45. **Omen не теряется молча.** Смена валюты сохраняет выбранный Omen; совместимость всегда показана.
    (`switching the currency keeps the omen held`)
46. **Статус цели считает ядро.** «Есть / докрафтить / не хватает / тир хуже / не fractured» и прогресс —
    `targetOutlook`, а не JSX. (`gives every requirement its own state against the current item`)
47. **Одна база — одна картинка.** Арт берётся из определения базы по `baseId`; исходный, текущий и цель
    одной базы показывают один и тот же файл. (`art.test.tsx`)


Инварианты выбора в пуле (редактирование исходного и цели):

48. **Выбранное — из реального состояния.** Строка «выбрана», только если этот мод есть в
    `source.explicits` или в `target.requirements`; это решает `sourcePickOptions` / `targetPickOptions`,
    а не флаг в компоненте. (`pick.test.ts`)
49. **Один тир на семейство.** Клик по другому тиру семейства, которое уже есть, заменяет мод исходного на
    его месте (fractured сохраняется) или переносит требование цели, а не добавляет дубль. Допустимость
    проверяется по предмету без старого тира — правила групп, слотов и ilvl те же.
    (`another tier of a family on the source replaces it…`, `…moves that requirement instead of duplicating it`)
50. **Выбор не сбрасывает пул.** После клика пул остаётся открыт на той же вкладке, семействе, поиске,
    теге и фильтре статуса; выбранная строка не исчезает из-за фильтра.
    (`ModifierPoolPanel.test.tsx`)

Инварианты v0.6 (ручная правка текущего предмета и контекстное меню, ADR 009):

51. **Ручная правка current — шаг истории, а не крафт.** `ManualEditStepRecord` (`kind: 'manual-edit'`)
    стоит в общей истории с craft-шагами, двигает только current, не тратит валюту и не использует
    бросок. (`a retier changes only current, costs nothing and is recorded as a manual step`)
52. **Undo / redo одинаковы для обоих видов шагов.** Redo возвращает записанный результат без нового
    броска; любой новый шаг — крафт или правка — стирает redo-ветку.
    (`craft → manual remove → manual fracture → craft…`, `a new manual edit or a new craft after undo…`)
53. **«Потрачено» — только craft-шаги.** Если в активной ветке есть ручная правка, панель затрат это
    показывает; оценки этапа от правок не меняются. (`asks once, then edits current only…`)
54. **Ручная правка ≠ игровая механика.** Удаление — не Orb of Annulment, fractured — не Fracturing Orb,
    повышение тира — не целевое улучшение. Настоящие механики будут отдельными вероятностными
    `CraftAction`. (`fracture and unfracture set the flag of that explicit — not a Fracturing Orb`)
55. **Правка соблюдает правила предмета.** Новый тир — только существующий тир того же семейства,
    новый мод — только разрешённый manual-edit пулом без заменяемого; ilvl и группы проверяются.
    (`"upgrade one tier" follows the real family list…`, `a retier keeps the item rules…`)
56. **Одно требование на семейство и из меню.** «Добавить в цель» переносит минимальный тир
    существующего требования семейства, а не создаёт второе. (`adds a new family, then moves the same family…`)

Инварианты v0.7 (входные сценарии, раскладка и язык, ADR 010):

57. **Новая сессия пуста.** При первом открытии нет ни исходного, ни текущего, ни цели, ни истории;
    демо-образцы сами не загружаются. (`a first visit is empty: start screen, empty target, no sample loaded`)
58. **Импорт — один путь и только с подтверждением.** Ctrl+V и кнопка «Импорт» используют одно
    распознавание и одно превью; до «Начать крафт» сессия не меняется; текст, не похожий на предмет, и
    вставка в поле ввода игнорируются. (`Ctrl+V with a game item opens the preview…`, `ignores text that is not an item…`)
59. **Активный крафт не заменяется молча.** Ctrl+V при наличии текущего предмета спрашивает; подтверждение
    сбрасывает историю и затраты, но сохраняет цель (с предупреждением о другой базе).
    (`asks first; confirming starts over and keeps the target…`)
60. **Исходный — сущность сессии, а не колонка.** На экране он свёрнут в строку и правится на отдельной
    поверхности теми же функциями настройки; правка после начала крафта не трогает current
    (рассинхрон и «Сбросить к исходному»). (`editing the starting item after crafting shows out-of-sync…`)
61. **Цель всегда на главном экране** рядом с текущим; «Взять текущий как основу» копирует требования
    «тир N+», а не выпавшие числа. (`"use current as base" copies tier requirements…`)
62. **Язык — представление.** Весь текст интерфейса — через типизированные ключи EN / RU, EN по умолчанию
    и как запасной; выбор хранится в localStorage; пакеты и расчёты от языка не зависят; в коде
    компонентов нет зашитого текста. (`i18n/core.test.ts`, `interface language` в `Entry.test.tsx`)

Инварианты v0.8 (веса PoE2DB, ADR 012):

63. **Вес — из таблицы своей группы.** База читает веса только из своей `WeightTable`; мод, которого
    там нет или который помечен «не измерено», имеет неизвестный вес на этой базе — значения других
    страниц, тиров, семейств и классов не подставляются. (`golden applicability … and weights`,
    `production applicability`)
64. **Неполные данные — без числа.** Если у любого кандидата пула вес неизвестен, вероятность
    `indeterminate: partial-weights`, а случайное добавление отказывает; «верхней границы» нет.
    (`gives no number when a competing weight is unknown`)
65. **Один пул для превью и броска.** Вес читается одной функцией (`CraftDbView.weightFor`) в записи
    пула; вероятность, обозреватель и `pickWeighted` используют одни и те же записи.
    (`preview probability and the sampler use the same pool`)
66. **Community-вес не выдаётся за игровой.** Каждая таблица несёт evidence: PoE2DB, recombinator-
    observation, community, дата снимка, патч, страница; сырое значение сохраняется.
    (`constructs a valid production CraftDB…`)
67. **Сопоставление не угадывает.** Строка PoE2DB → мод по стороне, уровню и имени, затем числам,
    тегам спавна и группам; ноль или несколько кандидатов — в отчёт unresolved. Текст — не ключ.
    (`tests/weights-pipeline.test.ts`)

68. **Палитра по умолчанию — применимое.** Режим «Применимые» показывает только смоделированные
    инструменты (сначала применимые к текущему предмету, затем Omen, затем заблокированные с причиной);
    «Все» — полный каталог, где несмоделированное отделено. Каталог в данных не сокращается.
    (`usable tools`, `currency + Omen craft…`)
69. **Источник шанса рядом с шансом.** Под процентом — короткая строка «Веса: PoE2DB · дата», подробности
    (метод, доверие, патч, группа) — в подсказке. Демо-веса без evidence такой строки не получают.
70. **В создании предмета — только реальные базы.** `[DNT]`, заготовки уников и базы вне официального
    трейда не предлагаются ни в шагах, ни в поиске; импорт Ctrl+V их по-прежнему распознаёт.
    (`base navigation over real data`, `base selector on real data`)

Инварианты патча после v0.8 (подписи семейств, ручное добавление, справка по инструментам, клавиши):

71. **Подпись семейства — из его тиров.** Обозреватель пула и меню мода называют семейство по шаблонам
    его собственных тиров (`familyTemplate`: различающиеся числа → «#»), а не по имени collision-группы —
    группу называет первый попавший в неё мод («#% increased Trap Damage» над тирами Spell Damage). Имя
    группы — только в колонке «Группа», причинах и пояснениях. Разные семейства с одинаковым текстом не
    сливаются; им добавляется уточнение (теги, иначе id семейства). (`family labels`,
    `production family labels`)
72. **Ручное добавление — правка, не крафт.** «+ Добавить префикс / суффикс» на текущем — `ManualEditStep`
    (`operation: 'add'`): без цены и броска, в истории, undo / redo, «потрачено» не меняется. Правила
    добавления — пул craft-session для этой стороны, свободный слот — по `AffixLimits`; React их не
    проверяет. Существующее семейство при добавлении не подменяется. (`manual add to a free slot…`,
    `"+ Add prefix" adds to a free slot by hand…`)
73. **ПКМ по инструменту — справка, не выбор.** Правый клик (Shift+F10, клавиша меню) по плитке палитры
    показывает описание и никогда не берёт инструмент; левый клик по-прежнему выбирает. Текст строит
    `toolInfo` из уже имеющихся данных (`mechanicNotes` / описание действия, `modifies`,
    `actionModifiers`, требования действия, статус, provenance); источник описания показывается
    отдельно, несмоделированное — «не смоделировано», механики не придумываются. (`tool info …`)
74. **Буквенные сочетания — по физической клавише.** Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl/Cmd+Y читают
    `KeyboardEvent.code` (`lib/shortcuts.ts`), поэтому работают на любой раскладке; в полях ввода
    сочетания остаются браузеру. Ctrl+V — событие `paste`, от раскладки не зависит. (`historyShortcut`,
    `history shortcuts on the page, Russian layout`)
